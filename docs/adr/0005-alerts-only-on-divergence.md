# 알림은 기상청 실황과 어긋날 때만 보낸다

푸시 알림은 앱을 열지 않은 유저에게 가치를 전달하는 유일한 수단이지만, 잦으면 그 즉시 삭제로 이어진다.
기상청이 이미 "비"라고 말하는 상황에 같은 내용을 또 알리면 그냥 중복 날씨 알림이고, 이 앱이 존재할
이유가 없다. 그래서 **기상청이 놓친 것을 알릴 때만** 발송하도록 조건을 좁혔다.

발송 조건은 세 가지를 모두 만족할 때다 — 관심 지역 격자에 최근 30분 내 서로 다른 유저의 강수 제보가
2건 이상, 그리고 기상청 실황은 강수 없음, 그리고 같은 지역에 최근 3시간 내 알림을 보내지 않았음.

## Consequences

- 알림은 **관심 지역(집·회사)** 기준이며 현재 위치를 쓰지 않는다. 백그라운드 위치 추적을 도입하면
  iOS "Always" 권한 소명, 배터리 소모, 그리고 원좌표 24시간 보관 정책(ADR-0002)과의 충돌이 한꺼번에
  따라오는데, 그 대가를 치를 단계가 아니다.
- 발송은 `pg_cron` 5분 주기 조건 검사 + Expo Push API 호출로 처리한다. 별도 서버가 필요 없다.
- 알림 빈도가 구조적으로 낮다. 유저가 알림을 받는 날은 드물지만, 받을 때마다 다른 데서 얻을 수 없는
  정보다. 이것이 의도한 트레이드오프다.

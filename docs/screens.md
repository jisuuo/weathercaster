# 화면 흐름

확정 전 초안. 결정 근거는 `docs/adr/`, 용어는 `CONTEXT.md`, 서버 계약은 `docs/data-model.md` 참조.

## 구조

하단 탭 2개. 그 이상은 없다.

```
┌─ 홈 (현재 위치 카드)        ← 진입 지점, 제보가 일어나는 곳
└─ 지도 (주변 제보)           ← "왜 다르지?"를 확인하는 곳
```

설정은 탭이 아니라 홈 우상단 아이콘으로 연다. 설정은 하루에 한 번도 안 열리는 화면이라 탭 자리를
차지할 자격이 없다.

바텀시트로 뜨는 화면(탭 아님): 제보 시트, 제보 상세, 관심 지역 편집.

## 홈

```
┌──────────────────────────────┐
│  서울 강남구 부근        ⚙︎   │
│                              │
│   ☁️  흐림                    │  ← 기상청 실황 (2시간 전 관측)
│   기상청 · 14시 관측          │
│                              │
│  ─────────────────────────   │
│                              │
│   🌧  근처 4명이 "비"          │  ← 유저 제보 (방금)
│   2km 내 · 가장 최근 3분 전    │
│                              │
│                              │
│                              │
│      ┌────────────────┐      │
│      │  지금 날씨 제보  │      │  ← 엄지 범위, 항상 같은 자리
│      └────────────────┘      │
└──────────────────────────────┘
```

**위아래 배치가 이 앱의 주장이다.** 위가 공식, 아래가 현장. 둘이 다를 때 그 차이가 화면 한가운데
가로선을 사이에 두고 드러난다. 같을 때는 아래가 "근처 4명도 흐림"이 되어 확인 역할을 한다.

기상청 블록에 **관측 시각을 반드시 표시한다.** 실황은 40~100분 지난 값이다(ADR-0006). 이걸 "지금"인 척
보여주면 유저는 우리가 왜 필요한지 영영 모른다. "14시 관측"이라고 적혀 있어야 "지금은 3시 반인데?"가
생기고, 그때 아래 제보 블록이 의미를 갖는다.

### 홈의 상태들

| 상황 | 아래 블록 | 제보 버튼 |
|---|---|---|
| 위치 권한 없음 | "위치를 켜면 근처 제보를 볼 수 있어요" | 활성 (누르면 권한 요청) |
| 위치 확보 중 | 스켈레톤 | 비활성 |
| 제보 0건 | "아직 근처 제보가 없어요. 첫 제보를 남겨보세요" | 활성 |
| 제보 있음 | "근처 4명이 비" | 활성 |
| 넓혀서 찾음 | "6km 밖에서 2명이 비" | 활성 |
| 엇갈림 | 아래 참조 | 활성 |

반경을 넓혀 찾았을 때 **거리를 밝히는 것이 규칙이다**(ADR-0002 계열 결정). 2km 안에서 찾은 4명과 8km
밖에서 찾은 2명은 신뢰도가 다르고, 그 판단은 유저가 해야 한다.

### 엇갈림 표시

```
   🌧 3명 "비"  ·  ☀️ 2명 "맑음"
   2km 내 · 의견이 갈리고 있어요
```

다수결로 하나를 고르지 않는다. "5명 중 3명이 비"로 뭉개면 **비가 막 그치는 중이라는 정보가 사라진다.**
그게 이 앱이 유일하게 알려줄 수 있는 것이다. 갈리는 상태 그대로 보여주고, 정렬은 제보 수 내림차순.

3종류 이상 갈리면 상위 2개만 보여주고 "외 2건"으로 접는다.

## 제보 시트

제보 버튼을 누르면 바텀시트가 올라온다. **여기서 5초가 결정된다.**

```
┌──────────────────────────────┐
│                              │
│      지금 날씨는?              │
│                              │
│   ☀️        ⛅️        ☁️      │
│   맑음    구름많음    흐림      │
│                              │
│   🌧        ❄️        ⋯       │
│    비        눈       기타     │
│                              │
└──────────────────────────────┘
```

- 6칸 그리드, 2행 3열. 한 화면에 다 보이고 스크롤이 없다
- **탭 한 번에 즉시 제출되고 시트가 닫힌다.** 확인 버튼 없음
- "기타"만 2차 시트를 연다 → 우박 / 강풍 / 안개 / 황사

확인 버튼을 없앤 이유는 5초 예산 때문이다. 콜드 스타트 1.5초, 위치 확보 1초, 시트 애니메이션 0.3초를
빼면 유저에게 남는 건 2초 남짓이다. 그 안에 고르고 확인까지 누르게 하면 예산을 초과한다.

오탭은 되돌릴 수 있게 한다 — 제출 직후 홈 하단에 "제보했어요 · 취소" 스낵바를 4초간 띄운다. 확인
버튼으로 모든 유저를 늦추는 대신, 실수한 소수에게만 되돌릴 길을 준다.

### 위치 권한 요청 시점

**제보 버튼을 처음 누른 순간**이다. 첫 실행 때 띄우지 않는다.

```
제보 버튼 탭
  ├─ 권한 있음 → 시트 열림
  └─ 권한 없음 → 왜 필요한지 1줄 설명 → OS 권한 다이얼로그
                   └─ 거부 → 시트 안 열림, "설정에서 켜기" 안내
```

맥락 없이 뜨는 권한 팝업은 거부율이 높고, iOS는 한 번 거부하면 앱 안에서 다시 물을 수 없다. 유저가
제보하려는 순간은 위치가 필요한 이유가 자명한 유일한 순간이다.

거부해도 앱은 계속 돈다 — 지도 탭에서 지역을 옮겨 다른 곳 날씨를 볼 수 있다. 다만 제보는 불가능하다.
제보는 "내가 지금 여기 있다"는 주장이고, GPS 없이는 그 주장이 성립하지 않는다.

## 낙관적 업데이트와 실패 처리

```
탭
 ├─ 즉시: 시트 닫힘 → 홈 카드에 내 제보 반영 ("3명" → "4명") → 스낵바
 └─ 백그라운드: submit_report RPC
      ├─ 성공 → 아무 일도 안 일어남 (화면은 이미 맞음)
      └─ 실패 → 카드 롤백 + 사유 표시
```

**조용히 롤백하지 않는다**(ADR-0003). 이 앱은 실패가 정상적으로 발생한다.

| 서버 예외 | 유저에게 보이는 문구 |
|---|---|
| `TOO_SOON` | 방금 제보하셨어요. 잠시 후 다시 시도해주세요 |
| `DAILY_LIMIT` | 오늘 제보는 여기까지예요 |
| `LOW_ACCURACY` | 위치가 정확하지 않아요. 실외에서 다시 시도해주세요 |
| `MOCK_LOCATION` / `IMPOSSIBLE_SPEED` | 위치를 확인할 수 없어요 |
| `BANNED` | 제보가 제한된 계정이에요 |
| 네트워크 오류 | 전송 실패. 다시 시도 (재시도 버튼) |

`MOCK_LOCATION`과 `IMPOSSIBLE_SPEED`를 같은 문구로 묶은 것은 의도적이다. "가짜 위치가 감지되었습니다"
같은 문구는 어뷰저에게 우리가 무엇을 검사하는지 알려주는 셈이다. 그리고 비행기 착륙 직후처럼 정상
유저가 속도 검증에 걸리는 경우도 있어서, 단정적인 문구는 억울함을 만든다.

## 지도 탭

```
┌──────────────────────────────┐
│                              │
│      🌧3                      │
│              ☁️1              │
│         ●내위치               │
│                    🌧2        │
│                              │
│  ┌────────────────────────┐  │
│  │ 기상청 실황: 흐림 · 14시 │  │  ← 하단 고정 바
│  └────────────────────────┘  │
└──────────────────────────────┘
```

- 핀은 제보 1건이 아니라 **격자 1칸**이다. 격자 안 제보자 수를 뱃지로 표시
- 지도를 움직이면 뷰포트 경계로 `reports_in_bounds` 재조회 (디바운스 400ms)
- 상한 500건에 걸리면 "지도를 확대하면 더 정확히 볼 수 있어요" 토스트
- 수명이 지난 제보는 사라지지 않고 흐리게(투명도 40%) 남는다 — "30분 전엔 비 왔음"이 정보다
- 하단 바에 그 지역 기상청 실황을 계속 띄운다. 지도에서도 비교 축을 잃지 않기 위해서다

핀 탭 → 제보 상세 시트.

## 제보 상세 시트

```
┌──────────────────────────────┐
│  🌧 비                        │
│  3명이 제보 · 가장 최근 5분 전  │
│  기상청 실황: 흐림 (14시)      │
│                              │
│  여기 지금 비 와요?            │
│  ┌─────────┐  ┌─────────┐   │
│  │ 맞아요   │  │ 아니에요 │   │
│  └─────────┘  └─────────┘   │
│                          🚩  │
└──────────────────────────────┘
```

- 확인/반박 버튼은 **내가 그 격자 반경 2km 안에 있을 때만** 활성. 밖이면 회색 + "가까이 있어야 투표할
  수 있어요"
- 내가 올린 제보에는 버튼이 안 보인다
- 🚩는 신고. 사유 3종(잘못된 정보 / 스팸 / 기타)

버튼 문구를 "좋아요"가 아니라 **"여기 지금 비 와요?"라는 질문 형태**로 둔 것이 핵심이다. "좋아요"는
제보가 마음에 드는지를 묻고, 질문형은 사실을 묻는다. `CONTEXT.md`에서 "좋아요"를 금지어로 박은 이유가
이것이다.

## 설정

- 알림 켜기/끄기
- 관심 지역 (최대 3개) — 추가는 지도에서 위치 찍고 이름 붙이기
- 개인정보처리방침 / 문의 (앱스토어 UGC 요건)
- 앱 버전

관심 지역 추가에 주소 검색을 넣지 않는다. 검색 API는 비용과 의존성이 늘고, 유저가 등록할 곳은 대개
집·회사 둘뿐이라 지도에서 찍는 편이 오히려 빠르다.

## 첫 실행 흐름

```
앱 실행
 └─ 백그라운드로 Supabase 익명 로그인 (유저는 아무것도 못 봄)
     └─ 홈 진입
         ├─ 권한 없음 상태로 표시
         └─ 첫 제보 시도 시 권한 요청
```

온보딩 화면이 없다. 튜토리얼도, 로그인도, 환영 화면도 없다. 홈 화면 자체가 설명이다 — 위에 기상청,
아래에 근처 제보, 그리고 버튼 하나. 이 앱은 설명이 필요할 만큼 복잡하지 않아야 한다.

## 미결

- **저밀도 격자 숨김**: 제보자 1명뿐인 격자를 지도에서 감출지(ADR-0002). 감추면 프라이버시가 오르지만
  초기 지도가 더 비어 보인다
- 위치 권한 거부 상태에서 홈이 어느 지역을 기본으로 보여줄지 (마지막으로 본 지역? 서울?)
